# 批次一：富文本消毒与安全响应头

## 问题

题库的题干、材料、选项与解析都以原始 HTML 存库，前端通过 `dangerouslySetInnerHTML` 渲染（`src/components/question/rich-html.tsx`）。写入侧唯一的防护是 `src/server/services/admin.ts` 里的正则黑名单：

```ts
.replace(/\son\w+="[^"]*"/gi, "")
.replace(/\son\w+='[^']*'/gi, "")
```

该正则只匹配被引号包裹的事件属性，以下写法全部可以穿透：

- `<img src=x onerror=alert(1)>`（属性值不带引号）
- `<svg onload=...>`、`<svg><animate onbegin=...>`
- `<iframe srcdoc="<script>...">`

更关键的是，这条防护只覆盖管理端表单。题库的主要数据来源是 `tools/saduck-scraper` 抓取的第三方站点 HTML，经 `prisma/import-saduck-tiku.ts` 入库时**完全不经任何消毒**。同时项目没有任何安全响应头，也没有 CSP 作为第二道防线。

结果：一条被污染的题面会在每个做题用户的浏览器里执行任意脚本。

## 方案

### 1. 用白名单消毒替换正则黑名单

新增 `src/server/content/rich-html.ts`，用 hast 生态（`hast-util-from-html` → `hast-util-sanitize` → `hast-util-to-html`）做「解析 → 白名单消毒 → 图片规范化 → 序列化」。

白名单基于 hast 默认的 GitHub schema 裁剪：

- **去掉** `input`（题库内容不需要表单控件）与所有内联 `style`（避免 CSS 注入）。
- **补上 MathML**：抓取数据里有 5182 个 `<math>` 元素，默认 schema 不含 MathML，直接套用会把所有数学题清空。白名单覆盖 `math/mfrac/msqrt/msub/msup/mrow/mi/mn/mo` 等 29 个标签及其常用属性。
- **补上** `u`、`font`、`caption`、`colgroup`，这些标签在实际抓取内容中出现过。
- 协议限制为 `http`/`https`（`href` 额外允许 `mailto`），`data:` 图片被拒绝。

图片规范化并入同一棵语法树处理，替换掉原先 `questions.ts` 里的正则 img 改写：协议相对地址 `//host/path` 升级为 `https:`，并补齐 `loading=lazy`、`decoding=async`、`referrerPolicy=no-referrer`、`alt`。

### 2. 三条路径统一接入

| 路径 | 位置 | 处理 |
| --- | --- | --- |
| 管理端录入 | `src/server/services/admin.ts` | `toHtml`/`stripTags` 改为 `toRichHtml`/`richHtmlToPlainText` |
| 抓取数据导入 | `prisma/import-saduck-tiku.ts` | 新增 `sanitizeQuestionHtml`，在 `upsertQuestion` 入口统一消毒题干、解析、材料与选项 |
| 读取渲染 | `src/server/services/questions.ts` | `normalizeRichHtml` 委托给 `sanitizeRichHtml`，作为历史脏数据的兜底 |

读取侧兜底的开销实测为**每次约 0.03ms**，一套 130 题的试卷额外开销约 15ms，可以接受。

### 3. 存量数据清洗

新增 `scripts/sanitize-stored-html.ts`（`npm run html:sanitize`），游标分批扫描 `Question`、`QuestionOption`、`Material`，重新消毒并同步刷新检索用的 `plainText`。默认试运行只统计，加 `--apply` 才写库；仅在内容变化时更新，可重复执行。

### 4. 安全响应头与 CSP

- `next.config.ts` 增加与请求无关的静态响应头：`X-Content-Type-Options`、`X-Frame-Options`、`Referrer-Policy`、`Permissions-Policy`、`Strict-Transport-Security`、`X-DNS-Prefetch-Control`。
- 新增 `src/middleware.ts`，逐请求生成 nonce 并下发 CSP。核心是 `script-src 'self' 'nonce-<随机值>' 'strict-dynamic'`，Next.js 会自动把同一个 nonce 注入它产出的所有 script 标签。开发模式额外放行 `'unsafe-eval'`（webpack HMR 需要）与 `ws:`。

`style-src` 保留 `'unsafe-inline'`：Tailwind 与 KaTeX 依赖内联样式，而样式内联不构成脚本执行面。

## 验证

`src/server/content/rich-html.test.ts` 新增 20 条用例，覆盖各类绕过手法与 MathML 保留：

```
✓ src/server/content/rich-html.test.ts (20 tests)
Test Files  32 passed | 1 skipped
     Tests  125 passed | 1 skipped
```

实机验证（生产构建 + `next start`，Chrome 无头）：

- 六项安全响应头与带 nonce 的 CSP 全部正确下发。
- 页面所有 script 标签均携带 nonce，**无 nonce 的 script 数量为 0**。
- 登录页正常渲染（6 个输入框），无水合错误、无失败请求。
- 模拟 `dangerouslySetInnerHTML` 注入 `onerror`、parser-inserted `<script>`、`<iframe srcdoc>`、`<svg><animate onbegin>` 四种向量，**实际执行数为 0**，浏览器控制台明确报告 CSP 拦截。

执行的命令：`npm run typecheck`、`npm run lint`、`npm test`、`npm run build`。

## 部署注意

存量题库需要执行一次清洗：

```bash
npm run html:sanitize            # 先试运行，确认待清洗条数
npm run html:sanitize -- --apply # 确认后写库
```

新增依赖 `hast-util-from-html`、`hast-util-sanitize`、`hast-util-to-html` 与开发依赖 `@types/hast`。

## 遗留

CSP 的 `style-src` 仍需 `'unsafe-inline'`。若后续要收紧，需要给 Tailwind 与 KaTeX 的内联样式改用 nonce 或 hash，改造成本较高，暂不处理。
